# MY REAL ESTATE LAB

전국 아파트 시세를 **직접 조사·검증해 입력하고**, 앱이 기록·계산·비교·시각화를 맡는 개인 공부용 웹앱입니다.
매물 중개나 투자 추천 기능은 없고, 외부 사이트에서 가격을 자동으로 가져오지도 않습니다.

## 가장 쉬운 방법: 파일 하나로 열기

`npm run build:single`로 만든 `dist-single/index.html` 파일을 더블클릭하면 설치 없이 바로 열립니다.
(Chrome·Edge 권장. 데이터는 그 브라우저에 저장되며, 지도 기능만은 아래 방법으로 실행해야 합니다.)

## 실행 방법 (처음 한 번)

1. **Node.js 설치**: https://nodejs.org 에서 LTS 버전을 내려받아 설치합니다. (20 이상)
2. **터미널 열기**: Mac은 `터미널`, Windows는 `PowerShell`.
3. 이 폴더로 이동합니다.
   ```bash
   cd Money-saver/real-estate-lab
   ```
4. 필요한 패키지를 설치합니다. (처음 한 번만, 1~2분)
   ```bash
   npm install
   ```
5. 앱을 실행합니다.
   ```bash
   npm run dev
   ```
6. 터미널에 나온 주소(보통 http://localhost:5173 )를 브라우저에서 엽니다.
   휴대폰에서 보려면 `npm run dev -- --host` 로 실행한 뒤, 같은 와이파이에서 터미널에 나온 `Network` 주소로 접속합니다.

끄려면 터미널에서 `Ctrl + C`.

### 그 밖의 명령

| 명령 | 하는 일 |
|---|---|
| `npm test` | 금액·날짜·변동률·가져오기 계산 테스트 실행 |
| `npm run build` | 배포용 파일을 `dist/` 폴더에 생성 |
| `npm run preview` | 빌드한 결과를 미리 보기 |

## 데이터는 어디에 저장되나요?

- 이 브라우저의 `localStorage`에 저장됩니다. 새로고침·재실행해도 유지됩니다.
- **다른 브라우저·다른 기기와는 공유되지 않습니다.** 브라우저 사이트 데이터를 지우면 함께 지워집니다.
- 그래서 **[백업] 화면에서 JSON 백업을 정기적으로 내려받아 두세요.** 같은 파일로 언제든 복원할 수 있습니다.
- 가져오기·삭제 직전 상태 1개는 [백업 → 직전 상태로 되돌리기]로 복구할 수 있습니다.

## 기존 Google Sheets 자료 가져오기

1. Google Sheets(2026 공부용 사본)에서 **파일 → 다운로드 → Microsoft Excel(.xlsx)**.
2. 앱의 **[백업] → 기존 Google Sheets(.xlsx) 가져오기**에서 파일 선택.
3. 미리보기(새 단지·가격 수, 확인이 필요한 지역 매핑)를 확인하고 **가져오기**.

| 원본 탭 | 가져오는 내용 |
|---|---|
| 시세트래킹 | 단지별·조사일별 매매·전세 (구역 제목 → 시·도, B열 → 시·군·구, C열 → 단지명·평형) |
| 전국 랜드마크 가격 순서 | 세대수·연식 (단지명이 정확히 같을 때만) |
| 수도권·광역시·중소도시·data | 가져오지 않음 — 같은 값을 지도·목록 모양으로 다시 보여주는 탭 |

- 가격 기준(실거래가/호가)이 적혀 있지 않으므로 모두 **가격유형 '기타' + '과거자료'**로 저장합니다.
- 평형(34")은 공급면적 기준이라 전용면적으로 바꾸지 않고 **평형 그대로** 둡니다. 단지 상세의 [면적 정보]에서 확인한 전용면적을 채울 수 있습니다.
- 전세 칸이 비어 있거나 0이면 값 없음으로 둡니다. 시트의 전세율 열은 쓰지 않고 앱이 다시 계산합니다.
- 서울 급지(1군~5군)는 단지 메모에 남깁니다.
- 지역 칸이 빈 행은 바로 위 행의 지역으로, 인천 옛 구(서구·중구·동구)는 2026.7 개편 후 구로 추정해 넣고 미리보기에 표시합니다.
- 같은 파일을 다시 가져와도 중복 기록은 생기지 않습니다.

## 2단계 화면

| 화면 | 내용 |
|---|---|
| 가격 비교 | 비교 목록(최대 8개) 단지의 매매·전세를 한 그래프에. 1년/3년/5년/전체, 실거래가·호가·기타 선택, 단지별 최근·최고·최저·최고점 대비 |
| 생활권 | 행정구역과 별개로 단지를 직접 묶기, 대표 단지·가격대·중앙값, 생활권 순위, 3/5/10억 가격 구간 그룹 |
| 후보 노트 | 저평가 후보 저장, 비교 단지와의 가격·연식·세대수 차이(사실만 계산), 가설·확인할 근거·입지/연식/면적/거래량 차이 직접 기록 |
| 단지 목록 | 비슷한 조건 필터(연식·세대수·전용면적·매매가 범위·생활권), 비교 목록 추가 버튼 |
| 단지 상세 | 교통·학군·생활 인프라 메모, 소속 생활권, [비교에 추가], [저평가 후보로 저장] |

비교 그래프 규칙
- 점 하나 = 실제 기록 하나. 기록이 없는 시점의 가격은 만들지 않습니다.
- 같은 시계열 기록 사이는 선으로 잇되, 6개월 넘게 비면 선을 끊습니다.
- 색 = 단지(목록 순서로 고정), 선 모양 = 가격 유형(실선 실거래가 / 긴 점선 호가 / 짧은 점선 기타), 굵은 선·채운 점 = 매매, 가는 선·빈 점 = 전세.
- 요약표의 수치는 선택한 기간 안의 기록만으로, 시계열(종류·유형)마다 따로 계산합니다.

저평가 후보 노트 규칙
- 앱은 '저평가'를 판정하지 않습니다. 가격 차이, 연식·세대수 차이, 그리고 주의사항(가격 유형 불일치, 기준일 차이, 면적 차이·전용면적 미확인, 과거자료)만 보여줍니다.
- 같은 가격 유형끼리 맞춰 비교하고(실거래가 → 호가 → 기타 순), 맞출 수 없으면 경고합니다.

## 3단계: 지도 (카카오맵)

### 처음 한 번 설정
1. https://developers.kakao.com 로그인 → 내 애플리케이션 → 애플리케이션 추가하기
2. 앱 설정 → 플랫폼 → **Web 플랫폼 등록** → 사이트 도메인에 `http://localhost:5173` 추가 (휴대폰으로 Network 주소를 쓰면 그 주소도 추가)
3. 제품 설정에 '카카오맵' 항목이 있으면 사용 설정 켜기
4. 앱 키의 **JavaScript 키**를 복사해 앱의 [지도] 화면에 붙여 넣기

키는 이 브라우저(localStorage)에만 저장되고 백업 파일·코드 저장소에는 들어가지 않습니다. `.env.local` 파일에 `VITE_KAKAO_JS_KEY=키` 로 넣어도 됩니다.

### 지도 규칙
- **위치를 확인한 단지만** 지도에 그립니다. 위치를 모르는 단지에 임의 좌표를 주지 않습니다.
- 위치는 카카오 장소·주소 검색 결과에서 **직접 고르거나**, 확인한 좌표를 직접 입력해야 저장됩니다.
- [위치 찾기]는 후보를 한꺼번에 검색해 확인 목록을 보여줍니다. 이름·분류(아파트)·지역이 모두 맞는 후보만 미리 체크되고, 저장은 확인 후에만 합니다.
- 라벨 색 = 대표 면적 최신 매매가 구간(네이비 진하기). 빨간 테두리 = 비교 목록에 있는 단지.
- 생활권을 고르면 소속 단지 위치를 이은 점선 영역을 그립니다. 실제 생활권 경계가 아닙니다.

## 국토교통부 실거래가 API (준비 단계)

앱(HTML)에는 인증키를 넣지 않습니다. 내 컴퓨터에서 도는 작은 프로그램(`server/`)이 키를 들고 국토부에 대신 물어봅니다.

1. `.env.local.example` 을 복사해 `.env.local` 로 저장하고 `MOLIT_SERVICE_KEY=` 뒤에 인증키(Decoding)를 붙여 넣기
2. 연결 테스트: `npm run molit:test` (기본: 서초구 아크로리버파크 전용 80~90㎡)
   - 다른 단지: `npm run molit:test -- --name 잠실엘스 --lawd 11710`
3. (다음 단계) `npm run molit:server` → http://127.0.0.1:8787 에서 앱 실행 + `/api/molit/sale|rent?lawd=&ym=` 제공

규칙: 해제(취소)된 매매는 최신가에서 제외, 전세는 월세 0원 계약만, 최근 1~2개월은 신고·공개 지연 가능. 조회 결과는 `server/.cache` 에 저장(git 제외).

## 데이터 원칙

- 금액은 **원 단위 정수**로 저장하고 화면에서만 억 원으로 보여줍니다. (`12.35` → `1,235,000,000원`)
- 값이 없으면 0이 아니라 `null` → 화면에는 "데이터 없음".
- 전세가율·변동률은 저장하지 않고 항상 원본 가격에서 다시 계산합니다.
- **실거래가 / 호가 / 기타는 서로 다른 시계열**입니다. 그래프에서도 다른 선(실선/점선)으로 그리고, 변동률도 같은 유형끼리만 계산합니다.
- 단지 목록·요약의 대표 가격은 최신 **실거래가 우선**, 없을 때만 호가·기타를 씁니다.
- 매매·전세 기준일이 90일 넘게 차이 나면 전세가율 옆에 경고를 표시합니다.
- 출처 URL이 없으면 "출처 미확인"으로 표시합니다.
- 기존 시트 등에서 가져온 과거 자료는 "과거자료" 표시를 붙여 구분합니다.
- 예시 데이터는 가상 단지(예시 A·B·C단지)이며 모든 화면에 "예시 데이터" 표시가 붙습니다.

## 데이터 구조 (Supabase 전환 대비)

`src/store/schema.ts`

| 엔터티 | 주요 필드 |
|---|---|
| Region | id, parentId, name, type(sido/sigungu/gu), adminCode, group(수도권/광역시/중소도시) |
| Apartment | id, regionId, name, address, builtYear, households, isLandmark, memo, transit/school/infraMemo, location(위도·경도·출처, 모르면 null) |
| ApartmentUnit | id, apartmentId, exclusiveArea(㎡, 모르면 null), pyeong(평형), label(84A 등) |
| PriceRecord | id, unitId, kind(매매/전세), amountWon, dealDate, surveyDate, priceType, sourceUrl, memo, entryId, legacy |
| StudyNote | id, date, regionId, apartmentId, title, content, source (화면 연결 예정) |
| LivingArea | id, name, description, apartmentIds, representativeId |
| Candidate | id, target(단지·면적), comparisons, hypothesis, evidenceToCheck, location/age/area/volumeDiff, status, conclusion |

각 엔터티는 id로만 서로를 참조하는 평평한 구조라서 그대로 DB 테이블로 옮길 수 있습니다.

## 폴더 구조

```
src/
  store/      데이터 모델(schema), 저장(storage), 상태(store), 변경 함수(ops)
  lib/        금액·날짜·변동률 계산(calc), CSV/JSON 백업(backup), 검증(validate) + 테스트
  data/       기본 행정구역 목록, 예시 데이터
  components/ 공통 UI(shadcn/ui 스타일), 그래프, 대화상자
  pages/      화면별 컴포넌트
```
